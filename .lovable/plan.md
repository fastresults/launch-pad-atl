## What I found

Hero images are generated by two Edge Functions (`venture-document-image`, `attendee-deliverable-image`) and stored in the private `venture-doc-images` bucket. Both correctly short-circuit when a `hero_image_path` already exists. The workflow is mostly right, but four real problems are causing extra generations, stale images, and orphaned files.

### Problem 1 — Race condition causes the same image to be generated 2-3x

Both `DocumentViewer.tsx` (Hub) and `workflow.$key.tsx` (Dashboard) auto-fire generation in a `useEffect` whenever `heroPath` is null. Generation takes ~8-15s. If the user opens the doc, closes, and reopens before the DB write lands — or simply navigates away and back — the second mount still sees `heroPath === null` and calls the function again. The function then re-checks the row, but by the time it does the first call may also still be mid-flight, so two model calls run, two PNGs upload (to `…/1.png` and `…/2.png` via `nextPath`), and credits are burned twice.

There is no in-flight lock at the DB level and no client-side debounce across mounts.

### Problem 2 — Rewriting a document doesn't refresh the image

`venture-generate-document` fires `venture-document-image` without `force` after every (re)generation. Because the row already has `hero_image_path`, the call no-ops. After a rewrite the user sees a hero that no longer matches the new content.

### Problem 3 — Old versions are never deleted

`nextPath` bumps `1.png → 2.png → …` on every forced regeneration, but only the newest path is stored on the row. Older PNGs stay in the bucket forever — invisible but billable.

### Problem 4 — Failed generation re-fires every mount

If the model returns 402/429/502, no row update happens, `heroPath` stays null, and the auto-effect re-triggers on the next render/refetch. There's no "tried and failed" marker.

## Plan

### 1. Add an in-flight lock in both image functions
Before calling the model, atomically claim the slot:
- `venture-document-image`: `UPDATE venture_documents SET hero_image_status='generating', hero_image_started_at=now() WHERE snapshot_id=? AND document_type=? AND (hero_image_status IS NULL OR hero_image_status='failed' OR hero_image_started_at < now() - interval '3 minutes') RETURNING id`. If no row returned → another worker owns it, respond `{ ok: true, skipped: true, reason: 'in_flight' }`.
- Same pattern for `attendee-deliverable-image` on `attendee_deliverables`.
- On success: set `hero_image_status='ready'`. On error: `hero_image_status='failed'`, `hero_image_error=<msg>`.

Migration adds three columns (`hero_image_status text`, `hero_image_started_at timestamptz`, `hero_image_error text`) to both `venture_documents` and `attendee_deliverables`. No new GRANTs (existing user/service grants cover them).

### 2. Client-side dedupe + respect status
In `DocumentViewer.tsx` and `workflow.$key.tsx`:
- Read `hero_image_status` alongside `hero_image_path`.
- Only auto-fire when `status` is `null` (never attempted). Treat `generating` as "wait", `failed` as "show a Retry button, don't auto-retry".
- Use a `useRef<boolean>` guard so a single component mount fires at most once per document_type per session.

### 3. Refresh image on rewrite
In `venture-generate-document`, after a successful rewrite (i.e., when `rewriteFeedback` is present OR content actually changed vs. previous version), call `venture-document-image` with `force: true`. Same for `dashboard-pipeline-run` → `attendee-deliverable-image` when feedback was provided.

### 4. Delete old version on forced regeneration
In both image functions, when `force=true` and an `existingPath` exists, `admin.storage.from(BUCKET).remove([existingPath])` after the new upload succeeds.

### 5. One-time backfill
Set `hero_image_status='ready'` for every existing row where `hero_image_path IS NOT NULL` so the new gating logic recognizes them as already done.

## Files touched

- `supabase/migrations/<new>.sql` — add columns, backfill
- `supabase/functions/venture-document-image/index.ts` — claim lock, status writes, delete-old on force
- `supabase/functions/attendee-deliverable-image/index.ts` — same
- `supabase/functions/venture-generate-document/index.ts` — pass `force: true` on rewrites
- `supabase/functions/dashboard-pipeline-run/index.ts` — pass `force: true` on rewrites
- `src/components/hub/DocumentViewer.tsx` — read status, ref guard, Retry on failed
- `src/routes/_authenticated/dashboard/workflow.$key.tsx` — same
- `src/lib/foundersHub.functions.ts` / `admin-member-view.functions.ts` — extend selects to include new status columns (the existing `select("*")` paths get them for free)
- `src/integrations/supabase/types.ts` — regenerated automatically by the migration

No UI redesign, no behavior change for the happy path — only fewer duplicate calls and an image that stays in sync with its document.
