
## Audit — what's shipping today vs. what should ship

Every deck (Foundation + 7) uses the same 6-slide skeleton plus one slide per deliverable:

```text
Cover → Stakes → What breaks → What good looks like → Deliverables overview
  → [one slide per deliverable, rendered by DeliverableSlide]
  → Recap / next
```

**Foundation earns its ticket.** Four written artifacts drafted live: Executive Summary, Vision/Mission, Problem/Solution, Value Prop.

**The other 7 are informational.** Each deliverable slide is `DeliverableSlide` (icon + name + tooltip). No worksheet, no calculator, no template, no generator, no artifact leaves the room. Attendees rightly feel Foundation delivered the $297 and the rest was framework recap.

The fix isn't more slides. It's making every stage produce **staff-generated, AI-assisted, ship-ready artifacts** the founder walks out clutching — signed, saved, and inheritable by the next stage.

## The productization model — same shape every stage

Every non-Foundation stage now ships three things founders can *see, touch, and use Monday morning*:

1. **Signature in-room build** — a 25-min live exercise where the founder gives inputs and the room produces a first draft on screen.
2. **AI-generated ship-ready artifact** — during the same session, workshop staff run a pre-built generator (Lovable AI Gateway → `google/gemini-3-flash-preview`) using the founder's Foundation + prior-stage inputs. Output is a formatted document (PDF/DOCX/MD) dropped into their dashboard **before they leave the room**.
3. **Founder-owned handoff kit** — the artifact plus a "how to use this Monday" checklist and the exact prompt/template so they can regenerate or extend it themselves.

Staff role: not lecturers — operators. Each stage has a **Staff Runbook**: which generator to run, what inputs to paste, what to review before releasing to the founder's dashboard, and the 3-question QA checklist before hitting "publish."

## Deck upgrade — structural changes

Extend each of the 7 decks from the current 6+N-slide skeleton to a **10+N skeleton**:

```text
Cover → Stakes → What breaks → What good looks like → Deliverables overview
  → [NEW] Signature build tool (what runs live)
  → [NEW] Live worksheet / walkthrough
  → [NEW] The AI-generated artifact (screenshot of the actual deliverable)
  → [NEW] Take-home kit (what leaves the room in your dashboard)
  → [one slide per deliverable — upgraded with build mechanic + inputs + takeaway]
  → Recap / next
```

**`DeliverableSlide` upgrade.** Extend props with optional `buildMechanic`, `inputs[]` (prior-stage outputs that feed it), `takeaway`, and `artifactPreview` (thumbnail of the AI-generated document). Backward-compatible so Foundation continues to render as-is.

## New systems this enables

### 1. `src/lib/workshop-generators.ts` — generator registry

A typed registry describing each stage's AI generator (id, title, model, prompt template, required inputs, output MIME, dashboard destination). Consumed by the Staff Runbook UI and by an edge function that actually runs the generation.

### 2. `supabase/functions/generate-artifact/index.ts` — server-side generator

One edge function, one shape:
```text
POST { generatorId, attendeeId, inputs }
  → loads prior-stage outputs from `attendee_deliverables`
  → runs `generateText` with the registered prompt (Lovable AI Gateway,
     model per generator, `Output.object` for structured docs)
  → renders to DOCX/PDF/XLSX/CSV via existing helpers
     (`markdown-to-docx.ts`, xlsxwriter, etc.)
  → uploads to `attendee-artifacts` storage bucket
  → writes an `attendee_deliverables` row
  → returns signed URL
```

Use `google/gemini-3-flash-preview` by default; upgrade specific generators (Legal Kit, Pitch Deck) to a stronger model as needed. Surface 429/402 errors to staff clearly.

### 3. `src/routes/_authenticated/_admin/admin.workshop-runbook.tsx` — Staff Runbook

A staff-facing screen (already inside the admin surface) that, for the active cohort:
- Lists attendees × stages in a grid
- One-click "Generate {Artifact}" per cell → calls the edge function, streams progress, shows preview, staff hits "Release to founder"
- 3-question QA checklist enforced before release
- Bulk actions per stage ("Generate all Strategy Briefs for this cohort")

### 4. Founder dashboard surfacing

New deliverable rows appear in the founder's existing deliverables view with document viewer + download. No new route needed — reuse `FilePreviewDialog` and the deliverables table.

## Recommended sequencing

Given the size, ship in three passes so you can review each:

1. **Pass 1 — Copy + deck structure (no AI):** Steps 1–6 above. All 7 decks upgraded with new slides and copy; new artifact previews are placeholder screenshots for now. Immediately delivers the promise on `/schedule` and in the decks.
2. **Pass 2 — Generator registry + edge function + one live stage:** Steps 7–8, wired to Strategy end-to-end as the pilot. Staff Runbook still manual (curl/postman) at this stage.
3. **Pass 3 — Staff Runbook UI + remaining 6 stages + storage/migration:** Steps 9–10, then port the remaining 6 generators.
