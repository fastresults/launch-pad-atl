# Why the PRD produces average sites — and how to fix it

I traced the full Website PRD pipeline (`venture-generate-document`, `venture-bulk-generate`, `_shared/deliverable-prompts.ts`, `_shared/prompt-profiles.ts`, `_shared/identity-guard.ts`). The prompt itself is not the main problem — it already asks for Awwwards-level output. The problem is what happens around it.

## What's actually wrong (verified in code)

1. **The PRD runs on the cheap model.** `venture-generate-document` line 392 reads `const modelId = isPrd ? modelForTier("flash") : ...` — with a comment directly above claiming it is "force-upgraded to Pro". It is not. The longest, most design-sensitive document in the system is generated by the fastest/cheapest model, and the master-prompt expansion pass (line 104) is also flash. This alone flattens layout imagination and copy quality.

2. **Startup Labs' own marketing is hardcoded into every founder's PRD.** `enforceWebsitePrdDepth` appends a fixed ~1,200-word addendum that says the site "should feel like Atlanta's most practical startup accelerator", references "the $197 workshop", "the three-hour format", "Founder Hub", and prescribes "Atlanta skyline textures" and "whiteboard strategy moments" as the imagery. This fires for every venture. It is the single biggest reason sites look same-y and off-brand: a UGC agency PRD gets accelerator imagery direction.

3. **Two conflicting document structures are sent at once.** The system prompt is `specialized prompt + track tone + profile.systemExtra`. The specialized prompt defines an 8-section PRD; `prompt-profiles.ts` `website_prd` simultaneously declares a *different* 14-section spine and 12–16 sections at 400–900 words each. The model gets contradictory outlines and hedges. `multiPass`/`batchSize`/`spine` in that profile are also dead config — no code path reads them.

4. **No design direction is ever chosen.** The prompt lists components (hero, feature grid, bento, pricing table, FAQ, CTA band) — the exact same list for every venture. There is no step that picks a *layout archetype* or *editorial personality* (e.g. brutalist editorial, luxury minimal, dense data-product, warm Main-Street storefront). Given an identical component menu and a generic model, every output converges on hero → 3-up features → pricing → FAQ. That is the "average" look.

5. **Imagery is words about images, never images.** The Imagery Plan is a table of text prompts. The downstream builder invents its own interpretation, so it lands on stock-photo generic. Nothing binds the plan to the venture's mood board beyond "anchor to the mood board URLs".

6. **Length ceiling risk.** 16k output tokens must hold a 2,800–3,800 word PRD *plus* a 1,800–2,400 word master prompt plus a full imagery table. Truncation triggers the expansion/repair passes, which stitch generic filler back in.

## Recommended fix, in priority order

**Phase 1 — Stop the bleeding (highest impact, smallest change)**
- Route `website_prd` to `MODELS.pro` for the main pass, the repair pass, and the expansion pass. Raise output budget and keep the 180s timeout.
- Delete the hardcoded Startup Labs addendum from `enforceWebsitePrdDepth`. Replace it with a venture-agnostic depth addendum generated *from the venture's own brand kit, track and offer* — or, when the master prompt is already ≥1,800 words, no addendum at all.
- Remove the conflicting `website_prd` entry from `prompt-profiles.ts` (or reduce it to `corpusQueries` + `corpusLimitPerQuery` only, which are the parts actually used) so one structure governs.

**Phase 2 — Give each site a real design direction**
- Add `_shared/site-art-direction.ts`: a library of 6–8 named layout archetypes, each with its own grid system, type personality, section rhythm, motion character, colour deployment and "signature move" (e.g. oversized editorial type + asymmetric split; full-bleed cinematic with sticky caption rail; dense bento product surface; warm textured storefront).
- Select the archetype deterministically from track + brand mood adjectives + voice, and inject the chosen one — with its specific grid, type scale and section rhythm — into the PRD prompt. One archetype per venture, not a menu.
- Forbid the default rhythm explicitly: no site may open hero → 3-up icon grid → logo bar. Require at least two archetype-specific signature sections per site.

**Phase 3 — Make the imagery actually art-directed**
- Bind every imagery prompt to the venture's mood-board images and locked palette by construction (composed in code from a shared image-prompt builder), not by asking the model to remember.
- Generate 2–4 real hero/key images at PRD time via the image model and embed their permanent URLs as `<img>` tags in the PRD, so the builder inherits the actual look instead of re-inventing it.
- Extend the identity guard to a **quality guard**: reject/repair when the imagery table is missing rows for any route, when fewer than N image prompts reference brand hexes, or when the master prompt lacks the archetype name.

**Phase 4 — Close the loop**
- Log per-PRD metrics (word count, imagery rows, archetype, model, truncation, repair passes fired) so quality regressions are visible instead of inferred.

- Cost: Pro-tier generation for one PRD per venture is a meaningful but bounded increase; image generation in Phase 3 adds 2–4 image calls per PRD.
